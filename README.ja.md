# Redmine Custom Field Manager

[English](README.md)

Redmine Custom Field Manager は、カスタムフィールドの並び順と、項目数の多いキー・バリューリスト（Key/value list）を安全に管理するためのRedmineプラグインです。Redmine標準の管理画面はそのままに、保存前にまとめて確認できる一括編集、CSVでの入出力、同時編集の競合対応、復元できる変更履歴といった機能を追加します。

バージョン `1.0.0` は最初の安定版です。プロジェクトの概要と操作ガイドは英語版の [`README.md`](README.md) を正本とし、製品の動作仕様は英語版の [`docs/specification.md`](docs/specification.md) に従います（日本語訳：[`docs/specification.ja.md`](docs/specification.ja.md)）。

## 導入すると変わること

専用の管理画面を新たに追加するのではなく、既存の**管理 → カスタムフィールド**を拡張します。

- カスタムフィールドを1つの一覧ですべて表示し、ドラッグ＆ドロップや複数選択で並べ替えられます。
- 並べ替えやキー・バリューリストの編集内容は、**変更を保存**を押すまでブラウザ上にだけ保持されます。**1つ戻す**、**1つやり直す**、**未保存の変更をすべて破棄**のほか、未保存のままページを離れようとしたときの警告も備えています。
- 標準の新規作成・編集・コピー・削除はこれまでどおり使えます。カスタムフィールドの削除は従来と同じく1行ずつ即座に実行される操作で、移動用の行選択とははっきり区別して表示します。
- キー・バリューリストの名称変更、有効・無効の切り替え、並べ替え、追加（1件ずつ・一括）、安全な削除を、保存前にまとめて編集できる1つの画面で行えます。
- キー・バリューリストをCSVに出力できます。インポートは「追加」「更新・追加」「全件同期」の3モードに対応し、書き込む前に変更内容をプレビューで確認できます。
- 同時編集を検知します。ほかの管理者の変更を黙って上書きせず、編集開始時点の内容、自分の変更、サーバー上の現在の内容を並べて表示します。
- 保存に成功するたびに変更履歴を記録します。カスタムフィールドの並び順やキー・バリューリストは、プレビューで確認したうえで対象全体を復元できます。カスタムフィールドの削除も監査用に記録しますが、プラグインから復元することはできません。

以下のスクリーンショットは、日本語ロケールのRedmine 7.0で撮影したものです。Redmineのバージョンや表示言語によって、ラベルが異なる場合があります。

### カスタムフィールドの並べ替え

- 行を個別にドラッグするか、1件以上の行を選択して、一覧のすぐ下にある折りたたみパネル**移動先を指定して移動**を開きます。このパネルは1件でも複数件でも同じように使えます。
- 移動先は名前で指定します。同じ名前のフィールドが複数ある場合は、現在の一覧上の位置を添えた候補が表示され、クリックで選べます。内部IDを調べたり入力したりする必要はなく、IDは参考情報として表示するだけです。
- チェックボックスは移動する行を選ぶためだけに使い、行ごとの操作は別の列に分けています。
- 未保存件数には、新しい並び順にするために必要な最小限の移動行数を表示します。100件の一覧で最後の行を先頭へ移動しても、100件の位置変更ではなく「未保存: 1件を移動」と表示されます。
- **このフィールドを削除**は、その行のフィールドだけを即座に削除します。確認メッセージには、対象のフィールド名に加えて、チェック中のほかの行には影響しないこと、そのフィールドの選択肢と保存済みの値も削除され、このプラグインでは復元できないことが表示されます。

![カスタムフィールドの並べ替え](docs/images/custom-field-ordering.png)

### キー・バリューリストの管理

- 最初に選択肢の一覧を表示し、そのすぐ下の**新しい選択肢**欄から1件ずつ追加できます。
- **選択項目の操作**は一覧の後ろに配置し、初期状態では折りたたんでいます。
- **一括追加**と**CSVエクスポート・インポート**は、たまに使う機能のため、さらに下にコンパクトな折りたたみツールとしてまとめています。
- その場での名称変更、有効化・無効化、削除、ドラッグ＆ドロップ、複数選択も利用できます。
- 鍵マークの付いた項目には、削除できない理由が表示されます。
- 保存前には、追加・更新・削除・移動の件数を表示します。保存は1つのトランザクションで行うため、一部だけが反映されることはありません。

![キー・バリューリストの編集](docs/images/enumeration-manager.png)

### 変更履歴と復元

- 拡張された各画面の**変更履歴**から、保存の記録の確認、対象全体の復元プレビュー、古い履歴の削除ができます。
- カスタムフィールド削除の履歴には、削除されたフィールドと、削除された値・選択肢の件数を監査用に表示します。安全に復元できないため、復元操作は表示しません。
- 履歴は既定では無期限に保存されます。プラグイン設定で、保存日数または世代数の上限を指定できます。

![変更履歴](docs/images/change-history.png)

## データの安全性

プラグインをインストールしただけで、既存のカスタムフィールド、選択肢ID、保存済みのカスタムフィールド値が書き換わることはありません。マイグレーションで作成するのは、リビジョン、履歴、インスタンス識別情報、確認済みの他環境CSVとの対応付けを保存するための、プラグイン専用の `rcfm_*` テーブルだけです。

通常の保存操作では、意図した変更をRedmine標準のカスタムフィールドと選択肢のレコードに反映しますが、既存のIDはそのまま維持します。現在使用中の選択肢や、既定値に設定されている選択肢は削除できません。その場合は一部だけを保存するのではなく、保存全体を取りやめます。並べ替え、一括編集、CSVインポート、復元は、いずれも履歴の記録と同じトランザクションで確定します。

プラグインを無効化または削除しても、Redmine標準のカスタムフィールド、選択肢、チケットなどに保存済みの値はそのまま残ります。プラグイン専用の `rcfm_*` テーブルも削除されずに残りますが、Redmineからは参照されないため、履歴が誤って失われることはありません。マイグレーションをバージョン0まで安易にロールバックしないでください。現在の履歴カラム拡張マイグレーションは、カラムを縮小すると保存済みのスナップショットが切り詰められるおそれがあるため、意図的にロールバックできないようにしています。プラグイン専用テーブルを完全に削除したい場合は、データベースをバックアップしたうえで、データベース管理者に内容を確認してもらってください。

## 対応バージョン

- Redmine 7.0.x
- Redmine 6.1.x
- Redmine 6.0.x

現在のCIでは、Redmine 7.0.2、6.1.5、6.0.11を、SQLite、MySQL 8.4、MariaDB 11.4、PostgreSQL 17の各データベースでテストしています。新しくリリースされたRedmineの系列には、互換性テストを経てから対応します。

## インストール

### 新規インストール

1. Redmineのデータベースをバックアップします。
2. このリポジトリを、Redmineのルートディレクトリ配下の `plugins/redmine_custom_field_manager` に配置します。ディレクトリ名は `redmine_custom_field_manager` から変更しないでください。
3. Redmineのルートディレクトリで、次のコマンドを実行します。

   ```sh
   bundle exec rake redmine:plugins:migrate RAILS_ENV=production
   ```

4. Redmineを再起動します。
5. 管理者としてログインし、**管理 → カスタムフィールド**を開きます。

### アップデート

1. Redmineのデータベースをバックアップします。本番環境では、アップデートのたびに必ず行ってください。
2. Redmineを停止します。
3. プラグインのファイルを置き換えます。
4. 新規インストール時と同じマイグレーションコマンドを実行します。
5. Redmineを起動します。

## 使い方

### カスタムフィールドを並べ替える

1. **管理 → カスタムフィールド**を開き、フィールドの種類のタブを選びます。
2. 行を目的の位置へドラッグするか、移動したい行を1件以上選択して、一覧のすぐ下にある**移動先を指定して移動**を開きます。
   - フィールド名はページ上に通常のテキストとして表示されるため、項目数が多い一覧でもブラウザの検索機能（`Ctrl+F` / `⌘+F`）が使えます。
3. 移動先のフィールド名を入力し、**前へ**または**後へ**を選んで、**選択したN件を移動**をクリックします。
   - 同じ名前の移動先が複数ある場合は、現在の一覧上の位置で区別された候補をクリックします。
4. 保存前の並び順を確認します。必要に応じて**1つ戻す**、**1つやり直す**、**未保存の変更をすべて破棄**を使います。
5. **変更を保存**をクリックすると、そのフィールドの種類の並び順全体が確定します。

### キー・バリューリストを編集する

1. **管理 → カスタムフィールド**で、形式が「キー・バリュー リスト」のカスタムフィールドを開き、**選択肢**の横にある**編集**をクリックします。
2. 選択肢を編集します。
   - 1件ずつ追加するときは一覧のすぐ下の**新しい選択肢**を、まとめて追加するときは**一括追加**（1行に1件）を使います。
   - 名称変更、有効化・無効化、削除は各行で行い、並べ替えはドラッグ＆ドロップで行います。
   - 複数の選択肢をまとめて操作するときは、対象を選択して**選択項目の操作**を開きます。
   - すでに使用されている選択肢は削除できません。代わりに無効化してください。
3. 保存前の変更内容を確認します。必要に応じて**1つ戻す**、**1つやり直す**、**未保存の変更をすべて破棄**を使います。
4. **変更を保存**をクリックします。それまでは何も保存されません。
   - 使用状況は保存の直前にも再確認します。その間に使用中になった選択肢があれば保存全体を中止するため、一部だけが保存されることはありません。

### CSVでインポート・エクスポートする

1. キー・バリューリストの編集画面に未保存の変更があれば、先に保存するか取り消します。CSVの操作は、常にデータベースに保存済みの状態を基準に行われます。
2. **CSVエクスポート・インポート**を開きます。
3. エクスポートするときは**現在の一覧をCSV出力**をクリックします。新しくファイルを作るときは**空のCSVテンプレートをダウンロード**をクリックすると、現在のフィールドに合わせた正しい列とメタデータを含むファイルを取得できます。
4. インポートするときは、CSVファイルとインポートモードを選びます。
   - **追加**: CSVの各データ行を、新しい選択肢として作成します。
   - **更新・追加**: このRedmine環境のIDを持つ行は既存の選択肢を更新し、ローカルIDのない行は新しく追加します。
   - **全件同期**: CSVに含まれないローカルの選択肢も処理の対象にします。使用中の選択肢は無効化のみ可能で、未使用の選択肢は削除か無効化を選べます。
5. **インポート内容をプレビュー**をクリックし、差分を確認します。インポートはどのモードでも、このプレビューを経る必要があります。
   - 別のRedmine環境から出力したCSVの場合、その環境のIDをローカルのIDとして扱うことはありません。候補との対応付けを確認するか、新規項目として作成するかを選びます。確認済みの対応付けは、次回以降のインポートでも再利用されます。
6. **この内容でインポート**をクリックすると、変更が保存されます。

### 同時編集の競合を解決する

1. ほかの管理者が同じ対象を先に保存していた場合、次に保存しようとしたときに競合画面が開きます。自分の未保存の変更は保持されたままです。
2. 編集開始時点の内容、自分の編集、サーバー上の現在の内容を見比べます。
3. 次のいずれかを選びます。
   - **編集を続ける**: 未保存の変更に戻って編集を続けます。
   - **破棄して再読み込み**: 自分の変更を破棄し、サーバー上の現在の内容を読み込みます。
   - **統合案を確認して保存**: 3-wayマージによる統合案を保存します。安全に統合できる場合にだけ表示され、このボタンを選ばない限り統合は適用されません。
   - **自分の変更で強制上書き**: サーバー上の内容を、明示的に自分の変更で置き換えます。この場合も削除の保護は回避できません。

### 履歴を確認・復元する

1. 拡張された各画面で**変更履歴**をクリックします。
2. 確認したい履歴の**表示**をクリックします。対象、操作、変更前後の内容は読みやすいラベルで表示され、生のJSONは折りたたまれた**技術情報（JSON）**欄にだけ残っています。
3. **復元プレビュー**をクリックし、有効・無効の状態を含む差分を確認します。
4. **対象全体を復元**をクリックします。個々の変更単位ではなく対象全体が復元され、復元操作そのものも履歴に記録されます。
   - プレビュー後に対象が変更された場合や、復元に安全でない削除が必要になる場合は、復元全体を中止します。

### 履歴の保存期間を管理する

- **保存期間を自動で制限する**: **管理 → プラグイン**を開き、Redmine Custom Field Managerの**設定**をクリックします。**保存期間（日）**、**対象ごとの最大世代数**のどちらか、または両方を入力し、**適用**をクリックします。空欄の項目は無制限になります。
- **履歴を手動で削除する**: **変更履歴**画面で履歴を選択して**削除**をクリックするか、**日時を指定して履歴を削除**を使います。

## 開発・テスト

このプラグインを配置したRedmineのルートディレクトリで、次のコマンドでテストを実行します。

```sh
bundle exec rake redmine:plugins:test NAME=redmine_custom_field_manager RAILS_ENV=test
```

GitHub Actionsでは、MySQL、MariaDB、PostgreSQLの実際の行ロックを使った同時実行テストと、Redmine 7.0.2上でのPlaywrightによるブラウザテストもあわせて実行しています。実装の詳細は [`docs/implementation.md`](docs/implementation.md)（日本語訳：[`docs/implementation.ja.md`](docs/implementation.ja.md)）、10,000件での性能測定結果は [`docs/performance.md`](docs/performance.md)（日本語訳：[`docs/performance.ja.md`](docs/performance.ja.md)）を参照してください。
