# Redmine Custom Field Manager

[English](README.md)

Redmine Custom Field Manager は、カスタムフィールドの並び順と、項目数の多いキー・バリューリスト（Key/value list）を安全に管理するためのRedmineプラグインです。Redmine標準の管理画面はそのままに、保存前にまとめて確認できる一括編集、CSVでの入出力、同時編集の競合対応、復元できる変更履歴といった機能を追加します。

現在のバージョン `0.1.0` は開発版です。プロジェクトの概要と操作ガイドは英語版の [`README.md`](README.md) を正本とし、製品の動作仕様は [`docs/specification.md`](docs/specification.md) に従います。

## 導入すると変わること

専用の管理画面を新たに追加するのではなく、既存の**管理 → カスタムフィールド**を拡張します。

- カスタムフィールドを一覧ですべて表示し、ドラッグ＆ドロップや複数選択で並べ替えられます。
- 並べ替えやキー・バリューリストの編集内容は、**変更を保存**を押すまでブラウザ上にだけ保持されます。**1つ戻す**、**1つやり直す**、**未保存の変更をすべて破棄**のほか、未保存のままページを離れようとしたときの警告も備えています。
- 標準の新規作成・編集・コピー・削除はこれまでどおり使えます。カスタムフィールドの削除は従来と同じく1行ずつ即座に実行される操作で、並べ替え用の選択とははっきり区別して表示します。
- キー・バリューリストの名称変更、有効・無効の切り替え、並べ替え、追加（1件ずつ・一括）、安全な削除を、保存前にまとめて編集できる1つの画面で行えます。
- キー・バリューリストをCSVに出力できます。インポートは「追加」「更新・追加」「全件同期」の3モードに対応し、書き込む前に変更内容をプレビューで確認できます。
- 同時編集を検知します。ほかの管理者の変更を黙って上書きせず、編集開始時点の内容、自分の変更、サーバー上の現在の内容を並べて表示します。
- 保存に成功するたびに変更履歴を記録します。カスタムフィールドの並び順やキー・バリューリストは、プレビューで確認したうえで対象全体を復元できます。カスタムフィールドの削除も監査用に記録しますが、プラグインから復元することはできません。

以下のスクリーンショットは、日本語ロケールのRedmine 7.0で撮影したものです。Redmineのバージョンや表示言語によって、ラベルが異なる場合があります。

### カスタムフィールドの並べ替え

行を個別にドラッグするか、1件以上の行を選択して、一覧のすぐ下にある折りたたみパネル**移動先を指定して移動**を開きます。このパネル名は選択件数ではなく移動先の指定方法を表しており、1件でも複数件でも同じように使えます。移動先の名前が一意であれば、名前を入力するだけで指定できます。同じ名前の項目が複数ある場合は、現在の一覧上の位置を添えた候補が表示されるので、クリックして選べます。内部IDを調べたり入力したりする必要はありません（IDは参考情報として表示するだけです）。チェックボックスは移動対象を選ぶためだけに使い、行ごとの操作は別の列に分けています。未保存件数には、新しい並び順にするために必要な最小限の移動行数を表示します。そのため、100件の一覧で最後の行を先頭へ移動しても、表示は「未保存: 1件を移動」になります。

**このフィールドを削除**は、常にその行のフィールドだけを即座に削除します。確認メッセージには、対象のフィールド名に加えて、チェック中のほかの行には影響しないこと、そのフィールドの選択肢と保存済みの値も削除され、このプラグインでは復元できないことが表示されます。

![カスタムフィールドの並べ替え](docs/images/custom-field-ordering.png)

### キー・バリューリストの管理

編集画面では、最初に選択肢の一覧を表示します。そのすぐ下にある**新しい選択肢**欄から、通常どおり1件ずつ追加できます。選択した項目に対する操作は一覧の後ろに配置し、初期状態では折りたたんでいます。一括追加とCSVはたまにしか使わない機能のため、さらに下にコンパクトな折りたたみツールとしてまとめています。このほか、その場での名称変更、有効化・無効化、削除、ドラッグ＆ドロップ、複数選択も利用できます。鍵マークの付いた項目には、削除できない理由が表示されます。保存前には未保存の変更をすべて件数で表示し、保存は1つのトランザクションで行うため、一部だけが反映されることはありません。

![キー・バリューリストの編集](docs/images/enumeration-manager.png)

### 変更履歴と復元

拡張された各画面の**変更履歴**から、保存の記録の確認、対象全体の復元プレビュー、古い履歴の削除ができます。カスタムフィールド削除の履歴には、削除されたフィールドと影響件数を監査用に表示しますが、安全に復元できないため復元操作は表示しません。履歴は既定では無期限に保存され、プラグイン設定で保存日数または世代数の上限を指定できます。

![変更履歴](docs/images/change-history.png)

## データの安全性

プラグインをインストールしただけで、既存のカスタムフィールド、選択肢ID、保存済みのカスタムフィールド値が書き換わることはありません。マイグレーションで作成するのは、リビジョン、履歴、インスタンス識別情報、確認済みの他環境CSVとの対応付けを保存するための、プラグイン専用の `rcfm_*` テーブルだけです。

通常の保存操作では、意図した変更をRedmine標準のカスタムフィールドと選択肢のレコードに反映しますが、既存のIDはそのまま維持します。現在使用中の選択肢や、既定値に設定されている選択肢は削除できません。その場合は一部だけを保存するのではなく、保存全体を取りやめます。並べ替え、一括編集、CSVインポート、復元は、いずれも履歴の記録と同じトランザクションで確定します。

プラグインを無効化または削除しても、Redmine標準のカスタムフィールド、選択肢、チケットなどに保存済みの値はそのまま残ります。プラグイン専用の `rcfm_*` テーブルも削除されずに残りますが、Redmineからは参照されないため、履歴が誤って失われることはありません。マイグレーションをバージョン0まで安易にロールバックしないでください。現在の履歴カラム拡張マイグレーションは、カラムを縮小すると保存済みのスナップショットが切り詰められるおそれがあるため、意図的にロールバックできないようにしています。プラグイン専用テーブルを完全に削除したい場合は、データベースをバックアップしたうえで、データベース管理者に内容を確認してもらってください。

## 対応バージョン

- Redmine 7.0.x
- Redmine 6.1.x
- Redmine 6.0.x

現在のCIでは、Redmine 7.0.2、6.1.5、6.0.11を、SQLite、MySQL 8.4、MariaDB 11.4、PostgreSQL 17の各データベースでテストしています。新しくリリースされたRedmineの系列には、互換性テストを経てから対応します。

## インストール

1. Redmineのデータベースをバックアップします。
2. このリポジトリを、Redmineのルートディレクトリ配下の `plugins/redmine_custom_field_manager` に配置します。ディレクトリ名は `redmine_custom_field_manager` から変更しないでください。
3. Redmineのルートディレクトリで、次のコマンドを実行します。

   ```sh
   bundle exec rake redmine:plugins:migrate RAILS_ENV=production
   ```

4. Redmineを再起動します。
5. 管理者としてログインし、**管理 → カスタムフィールド**を開きます。

アップデートするときは、Redmineを停止した状態でプラグインのファイルを置き換え、同じマイグレーションコマンドを実行してからRedmineを再起動します。本番環境をアップデートする前には、毎回必ずデータベースをバックアップしてください。

## 使い方

### カスタムフィールドを並べ替える

1. **管理 → カスタムフィールド**を開き、フィールドの種類のタブを選びます。
2. 行をドラッグするか、移動したい行を1件以上選択して、一覧のすぐ下にある**移動先を指定して移動**を開きます。
3. 移動先のフィールド名を入力し、**前へ**または**後へ**を選んで移動します。同じ名前の移動先が複数ある場合は、現在の一覧上の位置で区別された候補をクリックします。
4. 保存前の状態を確認します。必要に応じて**1つ戻す**、**1つやり直す**、**未保存の変更をすべて破棄**を使います。
5. **変更を保存**を押すと、そのフィールドの種類の並び順全体が確定します。

すべてのフィールド名はページ上に通常のテキストとして表示されるため、項目数が多い一覧でもブラウザの検索機能（`Ctrl+F` / `⌘+F`）が使えます。

### キー・バリューリストを編集する

標準のカスタムフィールド画面から、形式が「キー・バリュー リスト」のカスタムフィールドの選択肢を開きます。最初に一覧が表示されるので、1件ずつの通常の追加は、そのすぐ下の**新しい選択肢**から行います。名称、有効・無効、並び順、追加、削除の変更は、**変更を保存**を押すまで反映されません。一括追加とCSVは、選択項目の操作の下にあるコンパクトなツールから利用できます。

すでに使用されている選択肢は削除できないため、代わりに無効化してください。使用状況は保存の直前にも再確認します。その時点で状態が変わっていた場合は操作全体を中止するため、一部だけが保存されることはありません。

### CSVでインポート・エクスポートする

キー・バリューリストの編集画面で**CSVエクスポート・インポート**を開きます。

- **追加**: CSVの各データ行を、新しい選択肢として作成します。
- **更新・追加**: 同じ環境のIDを持つ行は既存の選択肢を更新し、ローカルIDのない行は新しく追加します。
- **全件同期**: CSVに含まれないローカルの選択肢も処理の対象にします。使用中の選択肢は無効化のみ可能で、未使用の選択肢は削除か無効化を選べます。

**空のCSVテンプレートをダウンロード**を使うと、現在のフィールドに合わせた正しい列とメタデータを含む新しいファイルを用意できます。エクスポートやインポートのプレビューを行う前に、画面上の変更を保存するか取り消してください。CSVの操作は、データベースに保存済みの状態を基準に行われます。

インポートはどのモードでも、適用前に差分のプレビュー確認が必要です。別のRedmine環境から出力したCSVの場合、その環境のIDをローカルのIDとして扱うことはありません。管理者が候補との対応付けを確認するか、新規作成を選ぶ必要があります。確認済みの対応付けは、次回以降のインポートでも再利用できます。

### 同時編集の競合を解決する

ほかの管理者が同じ対象を先に保存していた場合、次に保存しようとしたときに競合画面が開きます。自分の未保存の内容は保持されたままです。ここでは、編集を続ける、破棄して再読み込みする、安全に統合できる場合は3-wayマージによる統合案を確認する、自分の内容で明示的に強制上書きする、のいずれかを選べます。確認なしに統合が適用されることはなく、強制上書きでも削除の保護は回避できません。

### 履歴を確認・復元する

拡張された各管理画面の**変更履歴**を使います。対象、操作、変更前後の内容は読みやすいラベルで表示し、生のJSONは折りたたまれた技術情報欄にだけ残しています。復元する前には、有効・無効の状態を含む差分のプレビューが表示されます。復元は個々の変更単位ではなく、対象全体に対して行われ、復元操作そのものも履歴に記録されます。プレビュー後に対象が変更された場合や、復元に安全でない削除が必要になる場合は、復元全体を中止します。

履歴の保存設定は、**管理 → プラグイン → Redmine Custom Field Manager → 設定**で変更できます。保存期間と最大世代数を空欄にすると、無期限に保存されます。

## 開発・テスト

このプラグインを配置したRedmineのルートディレクトリで、次のコマンドでテストを実行します。

```sh
bundle exec rake redmine:plugins:test NAME=redmine_custom_field_manager RAILS_ENV=test
```

GitHub Actionsでは、MySQL、MariaDB、PostgreSQLの実際の行ロックを使った同時実行テストと、Redmine 7.0.2上でのPlaywrightによるブラウザテストもあわせて実行しています。実装の詳細は [`docs/implementation.md`](docs/implementation.md)、10,000件での性能測定結果は [`docs/performance.md`](docs/performance.md) を参照してください。
