# Redmine Custom Field Manager

[English (canonical)](README.md)

Redmine Custom Field Manager は、カスタムフィールドの並び順と大量の Key/value list を安全に管理するための Redmine プラグインです。Redmine 標準の管理画面を維持しながら、保存前の一括編集、CSV、競合確認、復元可能な変更履歴を追加します。

バージョン `0.1.0` は現在開発版です。英語の [`README.md`](README.md) をプロジェクト概要・操作ガイドの正本とし、製品動作の基準は引き続き [`docs/specification.md`](docs/specification.md) とします。

## 導入すると変わるところ

独立した管理画面を追加するのではなく、**管理 → カスタムフィールド**を拡張します。

- カスタムフィールドを全件表示し、ドラッグ＆ドロップまたは複数選択で並べ替えられます。
- 並べ替えと Key/value list の編集内容は**保存**を押すまでブラウザ内だけに保持されます。**1つ戻す**、**1つやり直す**、**未保存の変更をすべて破棄**、未保存時の離脱警告を利用できます。
- 標準の作成、編集、コピー、削除はそのまま利用できます。カスタムフィールドの削除は従来どおり即時に行う1行だけの操作で、移動用の選択とは明確に分けて表示します。
- Key/value list の名称、有効状態、順序、複数行の追加、削除を1つの保存前編集画面で扱えます。
- Key/value list をCSV出力し、追加、更新・追加、全件同期の各モードで、保存前の差分を確認してインポートできます。
- 同時編集を検知し、黙って上書きせず、編集開始時・自分の編集・サーバー現在値を比較できます。
- 保存ごとに変更履歴を記録し、カスタムフィールドの並び順またはKey/value list全体を、プレビュー後に復元できます。カスタムフィールド削除も監査用に記録しますが、プラグインからは復元できません。

以下は日本語ロケールの Redmine 7.0 で撮影した画面です。Redmine のバージョンや選択言語によりラベルは異なる場合があります。

### カスタムフィールドの保存前並べ替え

個別行をドラッグするか、折りたたまれた**まとめて移動**を開いて、選んだ複数フィールドを指定した移動先の前後へ移動できます。移動先の名称が一意なら名前だけで確定できます。同名項目が複数ある場合は現在の一覧位置を付けた候補が表示され、クリックで選べるため、内部IDを把握・入力する必要はありません。IDは補助情報としてのみ表示します。チェックボックスはまとめて移動だけに使い、各行の操作は別の列に分けています。未保存件数は新しい並びを説明する最小限の移動行数なので、100件中の最下行を先頭へ移しても「1件を移動」と表示します。

**このフィールドを削除**は、必ずその1行だけを即時に削除します。確認画面にはフィールド名、チェック中の他行へ影響しないこと、そのフィールド・選択肢・保存値が削除され、プラグインでは復元できないことを明記します。

![カスタムフィールドの保存前並べ替え](docs/images/custom-field-ordering.png)

### Key/value list 管理

名称編集、有効化・無効化、削除、ドラッグ＆ドロップ、複数選択、一括追加、CSV入出力を利用できます。鍵マークにマウスを重ねると削除できない理由を確認できます。保存前には未保存の変更件数を表示し、すべてを原子的に保存します。

![Key/value list の保存前編集](docs/images/enumeration-manager.png)

### 変更履歴と復元

拡張した各画面の**変更履歴**から、保存履歴の確認、対象全体の復元プレビュー、古い履歴の削除を行えます。カスタムフィールド削除の履歴には対象と影響件数を監査用に表示し、安全でない復元操作は表示しません。既定では無期限保存で、プラグイン設定から日数または世代数を指定できます。

![変更履歴](docs/images/change-history.png)

## データの安全性

プラグインの導入だけで、既存のカスタムフィールド、選択肢ID、保存済みのカスタムフィールド値を書き換えることはありません。マイグレーションで作成するのは、リビジョン、履歴、インスタンス識別情報、確認済みの別環境CSV対応関係を格納する、プラグイン専用の `rcfm_*` テーブルだけです。

通常の保存操作では、意図した変更を Redmine 標準のカスタムフィールド・選択肢テーブルへ反映しますが、既存IDは維持します。使用中または既定値の選択肢は削除できず、一部だけ保存するのではなく操作全体を中断します。並べ替え、一括編集、CSVインポート、復元は、履歴と一緒に原子的に確定します。

プラグインを無効化または削除しても、Redmine 標準のカスタムフィールド、選択肢、チケット等に保存済みの値は残ります。プラグイン専用の `rcfm_*` テーブルもそのまま残り、Redmine からは参照されないため、履歴を誤って破壊しません。現在の履歴列拡張マイグレーションは、縮小時のスナップショット切り捨てを防ぐため意図的に不可逆です。安易にマイグレーションをバージョン0まで戻さず、専用テーブルを完全に消す必要がある場合は、バックアップ後にDB管理者が対象を確認してください。

## 対応バージョン

- Redmine 7.0.x
- Redmine 6.1.x
- Redmine 6.0.x

現在のCIでは Redmine 7.0.2、6.1.5、6.0.11 を、SQLite、MySQL 8.4、MariaDB 11.4、PostgreSQL 17で試験します。新しい Redmine 系列は、互換性試験後に正式対応します。

## インストール

1. Redmine のデータベースをバックアップします。
2. このリポジトリを Redmine ルートの `plugins/redmine_custom_field_manager` に配置します。ディレクトリ名は `redmine_custom_field_manager` のままにしてください。
3. Redmine ルートで次を実行します。

   ```sh
   bundle exec rake redmine:plugins:migrate RAILS_ENV=production
   ```

4. Redmine を再起動します。
5. 管理者でログインし、**管理 → カスタムフィールド**を開きます。

更新時は Redmine を停止してプラグインファイルを入れ替え、同じマイグレーションコマンドを実行してから再起動します。本番更新の前には毎回データベースをバックアップしてください。

## 使い方

### カスタムフィールドを並べ替える

1. **管理 → カスタムフィールド**を開き、フィールド種別のタブを選びます。
2. 行をドラッグするか、**まとめて移動**を開いて移動する行を選びます。
3. 移動先のフィールド名を入力し、**前へ**または**後へ**を選んで移動します。同名の移動先が複数ある場合は、現在の一覧位置で区別された候補をクリックします。
4. 保存前の状態を確認します。必要なら**1つ戻す**、**1つやり直す**、**未保存の変更をすべて破棄**を使います。
5. **保存**を押し、そのフィールド種別の並び順全体を確定します。

全フィールド名は通常のテキストとして表示されるため、大量の一覧でもブラウザ検索（`Ctrl+F` / `⌘+F`）を利用できます。

### Key/value list を編集する

標準のカスタムフィールド画面から、形式が **Key/value list** のフィールドの選択肢を開きます。名称、有効状態、順序、追加、削除の変更は、**保存**を押すまで反映されません。

すでに使用されている選択肢は削除できません。代わりに無効化してください。使用状況は保存直前にも再確認し、状態が変わっていれば操作全体を中断して、部分的な保存を残しません。

### CSVを入出力する

Key/value list 編集画面の**CSVエクスポート・インポート**を開きます。

- **追加**は、CSVの各データ行を新しい選択肢として作成します。
- **更新・追加**は、同一環境のIDを更新し、ローカルIDのない行を追加します。
- **全件同期**は、CSVにないローカル項目も処理します。使用中の項目は無効化のみ、未使用項目は削除または無効化を選択できます。

**空のCSVテンプレートをダウンロード**を使うと、現在のフィールド情報と正しい列を持つ新規ファイルを取得できます。エクスポートまたはインポートのプレビュー前に、画面上の変更を保存するか取り消してください。CSV操作は保存済みのDB状態を基準にします。

すべてのインポートで、適用前に差分プレビューが必要です。別の Redmine 環境から出力したCSVでは、相手側IDをローカルIDとして扱いません。管理者が候補との対応を確認するか新規作成を選び、確認済みの対応関係は次回以降に再利用できます。

### 同時編集の競合を解決する

別の管理者が同じ対象を先に保存した場合、次の保存時に競合画面を開き、自分の未保存内容を保持します。編集を続ける、破棄して再読み込み、安全な場合の3-way統合案を確認する、自分の内容で明示的に強制上書きする、のいずれかを選べます。確認なしで統合せず、強制上書きでも削除保護は迂回できません。

### 履歴を確認・復元する

拡張された各管理画面の**変更履歴**を使います。対象、操作、変更前後は人間向けのラベルで表示し、生のJSONは折りたたんだ技術情報にだけ残します。復元前には有効／無効を含む差分を表示し、個別変更ではなく対象全体を復元します。復元操作自体も履歴に残ります。プレビュー後に対象が変わった場合や、安全でない削除が必要な場合は、復元全体を中断します。

保存設定は**管理 → プラグイン → Redmine Custom Field Manager → 設定**から変更します。保存期間と最大世代数が空欄なら無期限です。

## 開発・テスト

このプラグインを配置した Redmine ルートから、次を実行します。

```sh
bundle exec rake redmine:plugins:test NAME=redmine_custom_field_manager RAILS_ENV=test
```

GitHub Actions では MySQL、MariaDB、PostgreSQL の実行ロックを使った同時実行試験と、Redmine 7.0.2 上の Playwright ブラウザ試験も行います。実装上の説明は [`docs/implementation.md`](docs/implementation.md)、10,000件での実測は [`docs/performance.md`](docs/performance.md) を参照してください。
