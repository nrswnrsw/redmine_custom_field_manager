# 10,000件性能試験

[English](performance.md)

> この文書は参照用の日本語訳である。正本は英語版の [`performance.md`](performance.md) であり、内容に差異がある場合は英語版を優先する。

## 目的と方法

[仕様書](specification.ja.md)では、1リストあたり10,000件以上を性能目標としている。この試験では、ページネーションや仮想スクロールを使わず、全名称がDOMに存在する状態でこの目標を検証する。また、導入前に性能への影響を判断できるよう、標準Redmineとプラグイン導入時を比較する。

2026-10-22に次の環境で実測した。

- Redmine 7.0.2
- Ruby 4.0.6、Rails 8.1.4
- SQLite（test環境）
- Google Chrome 156.0.8078.48（Headless、Playwright 1.62.1で操作）
- macOS 27.0.1（Darwin 27.0.0）、ARM64
- 10,000件の選択肢を持つKey/value list

標準版とプラグイン版では、同じRedmineチェックアウト、データベース、カスタムフィールド、ブラウザ、ハードウェアを使用した。最初にプラグインなしでRedmineを起動し、次にプラグインありで再起動した。比較計測は各3回実行し、表には中央値と最小値〜最大値を示す。プラグイン単体の拡張ベンチマークは1回実行した。

## ベンチマークの実行方法

プラグインを導入した状態でデータを準備する。Redmineをtest環境で起動し、`RCFM_BASE_URL` でアクセスできる状態にする。ベンチマークは `admin` / `admin` でログインする。

```sh
RAILS_ENV=test bundle exec rails runner \
  plugins/redmine_custom_field_manager/test/performance/prepare_10000.rb
```

標準版を計測する場合はRedmineを停止し、プラグインをRedmineの `plugins` ディレクトリ外へ移動してから再起動し、プラグインのリポジトリチェックアウトにある比較スクリプトを実行する。

```sh
RCFM_FIELD_ID=<準備コマンドで出力されたID> \
RCFM_BASE_URL=http://127.0.0.1:3210 \
RCFM_VARIANT=standard \
RCFM_RUNS=3 \
RCFM_CHROME_PATH=<Chromeの実行ファイル（Playwright同梱のChromiumを使う場合は省略）> \
node /path/to/redmine_custom_field_manager/test/performance/compare_standard_10000.js
```

プラグイン版を計測する場合はプラグインのディレクトリを戻し、Redmineを再起動してから次を実行する。

```sh
RCFM_FIELD_ID=<準備コマンドで出力されたID> \
RCFM_BASE_URL=http://127.0.0.1:3210 \
RCFM_VARIANT=plugin \
RCFM_RUNS=3 \
RCFM_CHROME_PATH=<Chromeの実行ファイル（Playwright同梱のChromiumを使う場合は省略）> \
node plugins/redmine_custom_field_manager/test/performance/compare_standard_10000.js
```

プラグイン単体の拡張ベンチマークは次のように実行する。

```sh
RCFM_FIELD_ID=<準備コマンドで出力されたID> \
RCFM_BASE_URL=http://127.0.0.1:3210 \
RCFM_CHROME_PATH=<Chromeの実行ファイル（Playwright同梱のChromiumを使う場合は省略）> \
node plugins/redmine_custom_field_manager/test/performance/benchmark_10000.js
```

事前にプラグインのディレクトリで `npm install` を実行してPlaywrightをインストールしておく（Playwright同梱のChromiumを使う場合は `npx playwright install chromium` も実行する）。

## 標準Redmineとの比較

| 計測項目 | 標準Redmine | プラグイン導入時 |
|---|---:|---:|
| 一覧とSortableの準備完了 | 78.885秒（78.702〜80.265） | 21.920秒（21.808〜22.304） |
| DOM要素数 | 150,191 | 240,340 |
| input要素数 | 40,008 | 20,021 |
| DOMの行数／名称数 | 10,000／10,000 | 10,000／10,000 |
| 先頭行から末尾行への実際のD&D | 9.034秒（8.805〜9.037） | 13.070秒（12.894〜13.270） |
| 並び順の保存と再読み込み | 95.620秒（87.244〜96.291） | 28.899秒（28.257〜28.948） |
| D&D前のChrome JSヒープ | 43.5MB（42.5〜44.5） | 74.1MB（74.0〜74.3） |
| ブラウザJavaScriptエラー | 0件 | 0件 |

> **長距離移動に関する注記：** 「実際のD&D」は、先頭行のハンドルを末尾行まで物理的にドラッグする操作を指す。標準Redmineとの互換性を確認するために維持・計測している。10,000件の一覧で実用的に長距離移動する場合、プラグインでは、項目をチェックし、移動先の名称と前後を指定して「移動」を押す方法も利用できる。拡張ベンチマークにおける、この保存前のクライアント側移動処理は4.984秒であり、保存は別の操作である。

この環境では、プラグイン導入時は一覧の準備完了までの中央値が約72%、保存と再読み込みの中央値が約70%短くなった。名称は通常テキストとして表示し、必要なときだけ編集するため、input要素数は約半分になった。

一方、プラグインの選択操作、一括操作、変更のステージング、取り消しなどの管理機能にはクライアント側のコストがある。DOM要素数は約60%多く、D&D前のJavaScriptヒープ使用量は約70%多く、長距離D&Dは標準Redmineより約45%長かった。これらの割合は今回の環境での実測であり、改善率や上限を保証するものではない。

## プラグイン単体の拡張計測

既存のプラグイン単体ベンチマークでは、追加の操作を計測する。「初回ナビゲーション」は上の比較と同じSortable準備完了までは待たないため、2つの画面時間を直接比較してはならない。

| 操作 | 実測 |
|---|---:|
| 初回ナビゲーション | 3.168秒 |
| DOMの行数／通常テキストの名称数 | 10,000／10,000 |
| Sortable初期化 | 4.365秒 |
| 先頭行から末尾行への実際のD&D | 11.125秒 |
| 移動先の名称指定による先頭行から末尾行への一括移動 | 4.984秒 |
| 10,000件の並び順の保存と再読み込み | 29.264秒 |
| 保存後のSortable初期化（前の行に含まれる） | 4.907秒 |
| CSV出力（再初期化の待ち時間を除く） | 0.321秒 |
| 同一CSVの更新プレビュー | 0.672秒 |
| 復元プレビュー | 3.163秒 |
| Chrome JSヒープ | 約116.3MB |
| ブラウザJavaScriptエラー | 0件 |

## 判定

- 両方とも、10,000件の行と名称を正確に保持したまま、全件描画、実際の長距離D&D、保存、再読み込みを完走し、ブラウザJavaScriptエラーは発生しなかった。
- 今回の計測では、プラグインにより最も長い2つの待ち時間である初期準備と保存・再読み込みが大幅に短くなった。
- プラグインの追加管理機能によりDOM要素数とメモリ使用量は増え、長距離D&Dは遅くなった。メモリや処理性能に余裕のないクライアント端末では、このコストを考慮する必要がある。
- 拡張ベンチマークでは、一括移動、CSV出力・プレビュー、復元プレビューも、機能を削らずに完走した。
- 登録件数のハード上限は設けていない。ブラウザと端末性能の影響が大きいため、具体的な応答時間は保証しない。
- サーバー側の更新は500件単位の一括SQLで行い、10,000回の個別更新を避けている。

この記録はSQLite・単一プロセスの開発環境での実測値であり、本番DB、並行アクセスがある本番負荷、ほかのブラウザ、利用者の端末での値を保証するものではない。リリースごと、および対応するRedmine系列を追加するたびに再計測する。
