# 実装方針

この文書は [`specification.md`](specification.md) の要件を実現するための技術方針を記録する。製品動作は仕様書を優先する。

## 対応基準

2026-10-20 時点の公式保守対象である Redmine 7.0.2、6.1.5、6.0.11 のソースを比較して実装する。対象系列はいずれも `CustomField` の位置を STI サブクラス（フィールド種別）単位で管理し、`CustomFieldEnumeration` をカスタムフィールド単位で管理している。

## 画面の置換

Redmine のプラグインローダーがプラグインの `app/views` を View 検索パスの先頭へ追加する標準機構を利用する。Redmine 本体のファイルは変更しない。作成、編集、コピー、削除への既存リンクは維持する。

## 保存と競合制御

- 画面上の編集はブラウザ内に保持し、明示的な保存まで DB を更新しない。
- 保存要求には編集開始時の全体スナップショットの SHA-256 ダイジェストを含める。
- 保存時は対象スコープのリビジョン行、続いて対象レコードをロックし、ダイジェストを再計算する。
- 標準 Redmine の保存経路にも Rails のモデルコールバックで同じリビジョンロック順序を適用する。
- `CustomValue` は選択肢の使用状況が変化する作成・値変更・フィールド変更・削除時だけ対象リビジョンをロックする。保存直前に選択肢の存在をロック下で再検証し、削除と参照作成の競合で孤立参照を作らない。
- ダイジェストが異なる場合は書き込まず、HTTP 409 とサーバー現在値を返す。
- 競合画面には編集開始時、自分の編集、サーバー現在値の差分を表示する。サーバーと自分の変更が衝突しない場合だけ3-way統合案を返し、管理者の確定前には保存しない。
- 統合／強制上書きは確認したサーバーダイジェストを添えて再送し、確定直前に同じロック内で再照合する。再変更されていれば再び409にする。
- 並び順と履歴は同じ DB トランザクションで確定する。

カスタムフィールドの並び順、競合ロック、ダイジェストはフィールド種別単位で扱う。種別タブ内の保存で別種別の位置番号を更新しない。

## 履歴

履歴は対象スコープ、操作、操作者、変更前後のダイジェストと可逆差分を保持し、初回と20世代ごとに対象全体のスナップショットを保存する。履歴一覧は大きなJSON列をSELECTせず、詳細表示と復元時だけ読み込む。

任意履歴または指定日時以前の履歴を削除するときは、同じトランザクション内で削除区間の直後に残る最初の履歴だけを自己完結スナップショットへ変換する。保持期間／最大世代数による自動整理も同じ処理を使う。差分チェーンの境界だけを変換するため、全残存履歴を展開せずに復元可能性を維持する。

差分JSONとスナップショットJSONは、MySQL／MariaDBでも64 KiBを超える10,000件規模の履歴を欠損なく保存できる長さのテキスト列を使う。縮小時の切り捨てを避けるため、この列拡張マイグレーションは不可逆とする。

復元は対象全体だけを扱う。カスタムフィールド順序は現在と履歴のID集合が一致する場合に限り、名称等を変えず順序だけ復元する。Key/value list は履歴側IDがすべて現存するときだけ名称・有効状態・順序を復元し、現在だけにある項目を削除する必要があれば保存直前に使用状況を再確認する。安全に同じIDを復元できない場合は全体を中断する。

## CSV

- UTF-8 BOM付き、スキーマバージョン付きCSVを出力する。空リストでも出自を示すメタデータ行を出力する。
- 数式として評価され得るセルは先頭へアポストロフィを付け、専用フラグにより再インポート時に元の値へ戻す。
- 同一インスタンスかつ同一フィールドの更新では既存IDを維持する。存在しないIDはエラーにする。
- 別インスタンスではID一致を利用せず、管理者が確認したソースIDとローカルIDの対応だけを保存・再利用する。
- CSV解析、差分計画、最終適用を分離する。適用時はCSVと選択内容から計画を再生成し、プレビューダイジェストと編集開始時ダイジェストを再照合する。

## 大量更新

既存レコードの名称、有効状態、位置は、検証後に500件単位の引用済み`CASE`式で更新する。削除もID集合単位で行い、10,000件の移動で10,000回の個別`UPDATE`を発行しない。更新、履歴、マッピングは同じトランザクションに含める。

ブラウザは全名称を通常テキストとしてDOMへ保持する。仮想スクロールはブラウザ内検索要件に反するため採用しない。性能試験の方法と実測値は [`performance.md`](performance.md) に記録する。

## 既知の検証範囲

- 自動試験は Redmine 7.0.2／6.1.5／6.0.11 とSQLite、MySQL 8.4、MariaDB 11.4、PostgreSQL 17の組み合わせで実行する。
- MySQL／MariaDB／PostgreSQLでは実トランザクションと別DB接続を使い、選択肢削除と使用値作成が競合する双方の順序を試験する。SQLiteでは行ロックがないため、この2試験だけをスキップする。
- Redmine 7.0.2ではPlaywrightによる実ブラウザ試験で、編集・Undo/Redo・一括移動・保存・CSVプレビュー・2画面競合と安全な統合を確認する。
- DB直接更新や、モデルコールバックを意図的に迂回する未知のプラグインによる更新までは競合保護を保証しない。
